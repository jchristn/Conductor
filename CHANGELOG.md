# Changelog

## v1.1.0

- Added the `Anthropic` endpoint and VMR type for the Anthropic Messages API: `POST /v1/messages` (including streaming), `POST /v1/messages/count_tokens`, `GET /v1/models`, and `GET /v1/models/{id}`. Conductor sends the endpoint key in `x-api-key`, sends `anthropic-version` (client header, then the endpoint's new `AnthropicVersion`, then `Settings.Anthropic.DefaultVersion` of `2023-06-01`), and forwards `anthropic-beta`. Claude Code and the Anthropic SDKs work with `ANTHROPIC_BASE_URL` set to the VMR base URL and a Conductor credential.
- On Anthropic VMRs only, a Conductor credential is accepted in the `x-api-key` header. Other VMR types never accept it, and inbound `authorization`, `x-api-key`, and `anthropic-api-key` headers are never forwarded upstream for any family. See ADR 0005.
- Errors that Conductor generates on Anthropic VMRs now use the Anthropic error shape (`authentication_error`, `permission_error`, `not_found_error`, `rate_limit_error`, `overloaded_error`, `api_error`, `invalid_request_error`) and keep the `X-Conductor-Error-Code` header. Upstream errors pass through unchanged.
- Anthropic response headers `request-id`, `retry-after`, `x-should-retry`, and `anthropic-ratelimit-*` are now copied to the client, configured by the new `Anthropic` settings block (`ForwardedRequestHeaders`, `ForwardedResponseHeaders`, `ForwardedResponseHeaderPrefixes`).
- Message Batches (`/v1/messages/batches`) and Files (`/v1/files`) return `404` `not_found_error` on Anthropic VMRs, because they are stateful and not supported through Conductor.
- Model configurations on Anthropic VMRs map `MaxTokens` to `max_tokens`, inject `Temperature`, `TopP`, and `TopK` only before `Anthropic.SamplingParametersRemovedFromVersion` (`2026-10-21`), and never send `RepeatPenalty` or `ContextWindowSize`.
- Added decision models: the `TypeSafe` endpoint and VMR type for hosted Jev models and the endpoint-only `Ollaya` type for the local runtime, both speaking the TypeSafe System One API (`POST /v1/systemone`, `GET /v1/models`). Decision bodies with no questions, more than `TypeSafe.MaxQuestionsPerRequest` (default 64) questions, or invalid JSON are rejected with `400`. Model configurations are never applied to decision requests.
- Added a provider-neutral decision capability: `ModelDefinition.SupportsDecisions` (default `false`), `VirtualModelRunner.AllowDecisions` (default `true`, `403` when `false`), strict-mode `404` gating for decision and decision-only models, and the `Decisions` model access action (`Completions` does not imply it). Model load gained the `Decision` probe kind.
- Added the endpoint-only `OllamaCloud` type (Ollama wire API with a required Bearer key; no model management, keep-warm, or RigMonitor) and `OpenAICompatible` type (OpenAI wire API with an optional key; model load reports `Verified`, not `VerifiedRemote`).
- Replaced exact VMR and endpoint type matching with an explicit compatibility table: `Ollama` accepts `Ollama` and `OllamaCloud`; `OpenAI` accepts `OpenAI`, `OpenAICompatible`, and `vLLM`; `TypeSafe` accepts `TypeSafe` and `Ollaya`; `vLLM`, `Gemini`, and `Anthropic` accept their own type. Endpoint-only types are rejected as VMR types (`VmrApiTypeNotClientFacing`) through REST, MCP, and backup restore. See ADR 0006.
- Fixed request classification: every VMR now classifies requests by its configured `ApiType`, and a path outside that type's namespace returns `404` without being forwarded (for example, `/v1/chat/completions` on an Ollama VMR). Previously such requests could reach the upstream only because of how paths were classified. Use an `OpenAI` VMR with an `OpenAICompatible` endpoint for Ollama's `/v1` API.
- Removed the dashboard's hostname heuristics. Endpoint defaults now come only from the selected type, from a single provider registry, and the server applies the same type defaults on create to fields the request omits.
- Fixed upstream key exposure: endpoint `ApiKey` values are now masked (`****` plus the last four characters) in REST and MCP responses, and the new audited route `GET /v1.0/modelrunnerendpoints/{id}/apikey` returns the full value. The dashboard has a reveal control. Backups keep the real keys.
- Changed endpoint updates so an omitted or `null` `ApiKey`, or the masked value, keeps the stored key. Previously an omitted key was cleared. An empty string clears it.
- Added `HealthCheckEnabled` (when `false`, no probe is sent and the endpoint is treated as healthy), the `POST` health check method, and `HealthCheckRequestBody`. Hosted TypeSafe health checks use a one-question decision probe, are off by default, and run every 60 seconds when enabled; the dashboard explains the billing cost in a tooltip. Anthropic health checks are on by default every 60 seconds.
- Added validation codes `VmrApiTypeNotClientFacing`, `AnthropicApiKeyMissing`, `TypeSafeApiKeyMissing`, `OllamaCloudApiKeyMissing`, `AnthropicVersionInvalid`, `HealthCheckBodyRequired`, `DecisionsDisabledOnDecisionRoute`, and `OllamaCloudRigMonitorUnsupported` (errors), and `AnthropicConfigurationMismatch`, `ModelConfigurationSamplingIgnored`, `AnthropicHealthCheckUnauthenticated`, `TypeSafeConfigurationIgnored`, and `DecisionModelNotEnabled` (warnings). `EndpointApiTypeMismatch` is now based on the compatibility table.
- Request history and analytics now record `CacheCreationInputTokens`, `CacheReadInputTokens`, and `DecisionQuestionCount`, with additive columns on all four databases. Usage is parsed by the endpoint's configured type; for Anthropic, `TotalTokens` is input plus output tokens. The dashboard shows the new columns (hidden by default) and a provider filter on Analytics.
- Telemetry: new `api_family` values `Anthropic` and `TypeSafe`, span attributes `conductor.endpoint.api_type`, `conductor.anthropic.version`, and `conductor.decision.question_count`, and the `conductor_decision_question_count` histogram.
- The Inference First QoS profile now sends `AnthropicListModels`, `AnthropicGetModel`, `AnthropicCountTokens`, and `TypeSafeListModels` to the `metadata` class for newly seeded tenants.
- Fixed `conductor_create_vmr` in the MCP server: it now rejects unknown `api_type` values instead of falling back to `Ollama`, applies the API type rules, and returns violations as tool errors. MCP outputs mask endpoint keys, and the tool accepts `allow_decisions`.
- Default settings gained `x-api-key` and `anthropic-api-key` in `RequestHistory.RedactedHeaders` and `anthropic-version`, `anthropic-beta`, and `x-api-key` in CORS `AllowedHeaders`. Deployments with an explicit `RedactedHeaders` list must add the two headers manually.
- SDKs (C#, JavaScript, Python): added an `ApiType` definition with all nine types and the compatibility table, the new fields, the endpoint key reveal methods, and create, read, update, and delete methods for endpoints, model definitions, and virtual model runners. README examples cover Anthropic and TypeSafe resources and calling an Anthropic VMR with the Anthropic SDK.
- Dashboard: Anthropic "Connect a client" panel on VMRs, a TypeSafe decision question builder and Anthropic operations in the API Explorer, the `Decision` probe in the load model dialog, and VMR endpoint pickers filtered by the compatibility table.
- Added the `.github/workflows/tests.yml` CI workflow, which runs the backend, MCP, SDK, and dashboard test suites on Ubuntu, Windows, and macOS, plus `run-tests.sh` and `run-tests.bat` for each SDK.
- Fixed schema creation on SQL Server: the `modelaccessrules` table declared two cascading delete paths from `tenants`, which SQL Server rejects, so Conductor could not initialize a new SQL Server database. The table now cascades only through its policy.
- The shared test suite can now run against PostgreSQL, MySQL, and SQL Server by setting `CONDUCTOR_TEST_DB_TYPE` and the related `CONDUCTOR_TEST_DB_*` variables; each test gets its own database. The suite passes on all four database providers, and the CI workflow gained a provider matrix job that runs it against PostgreSQL, MySQL, and SQL Server containers.
- The CI workflow uses the runner temp disk for test databases on Windows and sets job timeouts.
- Recorded in README.md that native AOT is not supported, with the reasons.
- `Test.McpServer` accepts `--non-interactive` to exit after its tool tests (CI uses it), and now exits non-zero when setup fails.
- Fixed cross-tenant proxy access: a credential from a different tenant than the VMR now gets `403` with `X-Conductor-Error-Code: CredentialTenantMismatch` (`permission_error` on Anthropic VMRs) on every API family, whatever the model access settings; global admin users need a credential in the VMR's tenant, and system administrator API keys are exempt.
- Fixed tenant routes accepting requests without credentials: creating, updating, deleting, and purging a tenant now require a system administrator, reading one requires a global admin or system administrator, and listing works for any authenticated caller but shows users who are not global admins only their own tenant.
- Fixed `500` errors on writes without a tenant: a global admin user that omits `TenantId` on create, update, delete, validate, drain, resume, or quarantine now acts on its own tenant, and a system administrator gets `400` with `TenantId is required: ...`; reads without a tenant still return all tenants, and analytics saved reports are unchanged.
- Fixed `POST /v1.0/credentials` ignoring `UserId`: the credential now belongs to the named user, who must exist in the target tenant (`400` otherwise), an omitted `UserId` still means the caller, and a system administrator must supply one.
- Fixed the endpoint key reveal route being open to every user: `GET /v1.0/modelrunnerendpoints/{id}/apikey` now requires a tenant admin, global admin, or system administrator, and standard users get `401`.
- Fixed user responses returning passwords: create, read, list, and update responses no longer contain `Password`, and an update that omits `Password` keeps the stored one.
- Fixed dot segments and encoded separators bypassing proxy path checks: a proxied path with `.` or `..` segments, a backslash, or `%2e`, `%2f`, or `%5c` now returns `404` with `X-Conductor-Error-Code: UnsafePath` and is never forwarded.
- Fixed upstream cookies being stored and replayed to the upstream for every later client: cookies are disabled on all upstream HTTP clients, and `cookie` and `set-cookie` are always redacted in request history and are part of the default `RequestHistory.RedactedHeaders`.
- Fixed malformed JSON request bodies being reported as `502`: they now return `400` with `RequestBodyInvalid` (`invalid_request_error` on Anthropic VMRs) and are not forwarded.
- Fixed strict-mode rejections returning `401`: `StrictModeModelRejected`, `ModelNotAttached`, and `StrictModeNoModels` now return `404`, and `StrictModeModelRequired` returns `400`.
- Fixed decision gating and other Conductor-generated proxy errors missing their reason code: every API family now sends it in the `X-Conductor-Error-Code` header, for example `ModelDoesNotSupportDecisions`.
- Fixed `GET /v1/models` on a TypeSafe VMR alternating between `404` and `200`: it is now routed only to `Ollaya` endpoints, and a VMR with only hosted TypeSafe endpoints returns `404` with `ModelListingUnsupported`.
- Fixed a decision body whose `questions` is an array being reported as invalid JSON: the `400` message now says that `questions` must be an object keyed by question id.
- Fixed endpoint updates skipping the compatibility table: changing an endpoint's `ApiType` to one that an attached VMR does not accept now returns `400` `EndpointApiTypeMismatch` on field `ApiType`, naming the VMRs.
- Fixed `Ollaya` and `OpenAICompatible` endpoints silently using port 11434: a create without `Port` now fails with the new `PortRequired` validation code, and an update that omits `Port` keeps the stored port.
- Fixed empty ids in `ModelRunnerEndpointIds`, `ModelDefinitionIds`, and `ModelConfigurationIds` returning `500`: they now return `400` with `EndpointMissing`, `ModelDefinitionMissing`, or `ModelConfigurationMissing`, through REST and the MCP `conductor_create_vmr` tool.
- Fixed the endpoint validate route ignoring type defaults: a new draft now gets the type defaults before validation, as on create, so the README's Anthropic example no longer warns with `AnthropicHealthCheckUnauthenticated`.
- Fixed validation messages: the compatibility error now reads `virtual model runners of type OpenAI accept only endpoints of type OpenAI, OpenAICompatible, vLLM`, an endpoint-only VMR type reports only `VmrApiTypeNotClientFacing`, an unknown enum value returns `The value of 'ApiType' is not valid. Valid values: ...`, and `HealthCheckAuthRequiresApiKey` is no longer reported for `Anthropic`, `TypeSafe`, and `OllamaCloud` endpoints, which report their own missing-key error.
- Fixed new endpoints taking up to two health check intervals to become healthy: Conductor now probes an endpoint immediately on create, on startup, and when its probe target changes, and the first success marks it healthy, after which the normal interval and thresholds apply.
- Fixed a second server on the same port starting silently and running health checks: the server now exits with code `1` and a clear message when its port is in use, and the new `Webserver.StartupTimeoutMs` setting (default 10000, minimum 1000, maximum 300000) bounds how long startup waits for the listener.
- Fixed responses echoing request headers: `Host`, `Accept`, `Accept-Language`, and `Accept-Charset` are no longer sent as response headers.
- Fixed deleting a VMR or tenant with request history returning `500`: the delete now removes the request history rows, analytics events, and detail files first and returns `204`.
- Fixed `Test.McpServer` writing prompts in a loop when standard input is closed: interactive mode now exits at end of input.
- Fixed the Postman collection's Tenants and Administrators folders sending the tenant bearer token to routes that require a system administrator: both folders now send the new `adminApiKey` variable in the `x-admin-apikey` header.
- Fixed `POST /v1.0/users` storing the password `password` when the body omitted `Password`: a create without a non-empty `Password` now returns `400`. Existing users and updates (an omitted `Password` keeps the stored one) are unchanged. Administrator create already required `Password`.
- Fixed request bodies with an empty or `null` value for a required field (for example `"Password": ""`) returning `500`: they now return `400` naming the field.
- Fixed endpoint and VMR `load-model`, `keep-warm/run`, `runtime-stats/reset`, `runtime-backoff/clear`, and Ollama model pull and delete using the read tenant rule: a system administrator without `tenantId` now gets `400` with `TenantId is required: ...`, and a global admin user without it acts on its own tenant, as on other writes.
- Fixed health checks starting before the webserver listener: health checks, keep-warm, and request history cleanup now start only after the listener is verified, so a server that exits because the listener did not start within `Webserver.StartupTimeoutMs` never probes endpoints. Endpoints are still probed immediately once the listener is up.
- Fixed a new endpoint that shares its health check URL with an existing endpoint staying unhealthy (and VMR requests returning `502`) for up to about 1 s after create: registering an endpoint now wakes the shared health check loop, so the endpoint is probed at once.
- Fixed `POST /v1/messages/count_tokens` forwarding a malformed JSON body upstream: it now returns `400` with `RequestBodyInvalid` (`invalid_request_error`) like `/v1/messages`.
- Documentation: README.md, DOCKERHUB_README.md, REST_API.md, MCP_API.md, TELEMETRY.md, and QOS_OVERVIEW.md cover the new types, an "Upgrading to v1.1.0" section, Claude Code setup, and decision models. Added ADR 0005 (Anthropic provider) and ADR 0006 (decision models and explicit types). The Postman collection gained requests for every new endpoint type, the reveal route, validation examples, and a Proxied APIs folder with Anthropic and Decision requests, plus descriptions on every folder and request.
- Updated project, dashboard, SDK (C#, JavaScript, Python), release, and deployment versions to v1.1.0.

## v0.6.1

- Request timeouts: `TimeoutMs` on virtual model runners and model runner endpoints now defaults to 300,000 ms everywhere (model, setter fallback, data-row loading and all four database schemas). Previously the API, schemas and model defaulted to 60,000 ms while the dashboard used 300,000 ms. A startup warning lists records still at the old 60,000 ms default; they are not changed automatically.
- When Conductor's own time-to-first-byte deadline expires, the proxy now returns `504 Gateway Timeout` with `Code: "UpstreamTimeout"`, an `X-Conductor-Error-Code: UpstreamTimeout` header, and a message naming the endpoint, the limit and whether the VMR or endpoint set it. Previously it returned `502 Proxy error: A task was canceled.` Request history records the 504.
- The proxy HTTP client no longer applies its own timeout alongside the per-request deadline, and editing an endpoint's `TimeoutMs` no longer disposes a client that in-flight requests are using.
- Fixed `load-model` and Ollama model management (list, pull, delete) being cut off after 100 seconds regardless of `TimeoutMs`: the transport's HttpClient now has no timeout of its own, and each call is bounded only by its `TimeoutMs`.
- Added the `RunnerLoadTimeout` model load outcome for Ollama's `timed out waiting for llama-server to start`, with a hint to raise `OLLAMA_LOAD_TIMEOUT`. Proxied responses carrying that error pass through unchanged with `X-Conductor-Error-Code: RunnerLoadTimeout` and are recorded under that analytics error type.
- The VMR `effective` response now includes `RequestTimeoutMs` and, per endpoint, `TimeoutMs` and `RequestTimeout` (effective value, source and description). The dashboard's Effective Config view shows them.
- Dashboard: the VMR and endpoint timeout fields are now labelled "Time to first byte (ms)", with help text explaining what the limit covers and that the smaller value applies.
- Added keep-warm for virtual model runners (`KeepWarm` settings: `Enabled`, `Models`, `IntervalMs`, `KeepAlive`, `TimeoutMs`). A background service checks residency on eligible Ollama endpoints with `/api/ps` and loads models that are not resident. Each warm-up load takes one of the endpoint's `MaxParallelRequests` slots; a busy endpoint is retried at the next interval, and passes run one at a time. New routes `GET /v1.0/virtualmodelrunners/{id}/keep-warm` and `POST .../keep-warm/run`, a `keepwarm` column with migrations for all four databases, validation warnings, and dashboard settings plus status and Run now in Effective Config.
- Fixed build warnings from a vulnerable transitive `System.Security.Cryptography.Pkcs` (9.0.18, via Microsoft.Data.SqlClient 7.1.1) by referencing 10.0.13 directly. Updated NuGet packages: Microsoft.Data.Sqlite 10.0.13, MySql.Data 26.10.0, OpenTelemetry 1.20.1, Watson 7.3.2, QoSKit 0.2.2, Voltaic 2.4.0, SyslogLogging 2.4.1, RestWrapper 3.3.2, PrettyId 2.0.2, JsonMerge 1.1.1, Touchstone 0.2.1, and test SDK/adapters.
- Dashboard tables: the Columns selector now sits in each table's pagination bar (including Request History's server-paged bar) instead of a separate button above the table. Column choices are remembered per table, with Defaults and Show all actions. Every table's default columns were chosen so that no table scrolls horizontally at 1280x800 or wider: ID columns are hidden by default except on Tenants, along with lower-value columns (VMR load balancing, model access, reservation and history; endpoint RigMonitor and uptime; reservation tenant and enabled; configuration and user created dates; request method, access decision and source IP). All remain available from the selector. Date columns widened so timestamps fit on one line; the pagination bar stays visible while a table reloads. The QoS Monitor per-class table (Rejected / Timed out / Aborted merged; recent timestamps show the time only) and the Analytics user/credential breakdowns (TTFT average, P95 and coverage merged; unknown token usage shown under Tokens; forced 1120px minimum width removed) also fit without horizontal scrolling.
- Dashboard charts: one time picker (Last Hour / Day / Week / Month), refresh button and copy-image button now sit on the chart tab bar and drive every chart tab (Request history, Volume / TTFT, Latency / TTFT, Tokens, Heatmap) instead of living inside the Request history chart. The selection is kept across tabs and remembered between visits. Volume, latency and token trends now follow the selected range instead of always showing the last day, and the heat map no longer has its own Timeframe selector on the Dashboard.
- Observability > Analytics: added a Heatmap tab. It follows the page's time range (a custom range uses the smallest preset window that covers it), the tenant and request filters, and the page's refresh button.
- Documented request timeout semantics, cold model loads, `OLLAMA_LOAD_TIMEOUT`, keep-warm, and warming with `load-model` in README.md and REST_API.md. Updated release and deployment image tags to v0.6.1.

## v0.5.1

- Set .NET project versions to `0.5.1`.
- Updated .NET dependencies: `JsonMerge` (1.0.1 to 1.1.0), `Microsoft.Data.SqlClient` (7.1.0 to 7.1.1), `RestWrapper` (3.3.0 to 3.3.1), `SyslogLogging` (2.2.2 to 2.3.1), `Watson` (7.2.0 to 7.2.2), `Voltaic` (2.0.0 to 2.2.1), `Touchstone.Core`, `Touchstone.Cli`, `Touchstone.XunitAdapter`, and `Touchstone.NunitAdapter` (0.1.12 to 0.2.0), `coverlet.collector` (10.0.1 to 10.1.0), and `NUnit` (4.6.1 to 5.0.0).
- MCP behavior changes from Voltaic 2.1/2.2: tool arguments that fail the input schema (a missing required parameter or a wrong type) now return a result with `isError: true` naming the problem instead of a JSON-RPC `-32602`; an `initialize` naming an unknown protocol version is answered with the newest supported handshake revision (`2025-11-25`) instead of `-32602`; and `ping` under the stateless `2026-07-28` revision returns `-32601` (HTTP `404`), since that revision has no `ping`. Unknown tools still return `-32602`. `MCP_API.md` is updated to match.
- Updated the MCP tests for Voltaic 2.2: the `Test.McpServer` harness now connects with the base URL and the `/mcp/rpc` and `/mcp/events` paths, and relies on `ConnectAsync` for the `initialize` handshake instead of sending a second `initialize`; the shared MCP integration tests assert the new invalid-argument, unknown-version, and stateless `ping` behavior.
- Fixed the Analytics page being wider than the browser window: the 11-column User and Credential breakdown tables now scroll inside their cards instead of widening the whole page. Also fixed the Backup & Restore page scrolling sideways because its hidden file input was stretched to full width.
- Reorganized the dashboard navigation from 20 flat sidebar entries into 8 pages in two labeled sections (**Workspace**: Dashboard, Virtual Runners, Endpoints, Models, Traffic (QoS), Observability; **Administration**: Access, System). Related pages are now tabs on one page, with the active tab kept in the URL (`?tab=`) so it can be bookmarked. Old page URLs redirect to the matching page and tab and keep their query parameters, and each table keeps its saved rows-per-page setting. Replay Tour and Setup Wizard moved to a **?** help menu in the page header, and the guided tour now walks the new pages. The Analytics page's own section selector now uses `?view=` (old `?tab=` Analytics links are converted) and is shown as a segmented control so it is not confused with the page tabs.
- Added a seeded **Inference First** QoS profile and a `metadata` traffic class. The profile is a two-band priority queue that admits inference and embedding requests ahead of model list and model info requests (`OpenAIListModels`, `GeminiListModels`, `OllamaListTags`, `OllamaListRunningModels`, `OllamaShowModelInfo`), so health checkers polling through a VMR cannot starve real traffic. It is seeded once per tenant, including existing tenants on their next startup (guarded by the `qosInferenceFirstSeeded` tenant tag), and is not linked to any VMR automatically.
- Added `Webserver.TrustedProxies` (IP addresses or CIDR ranges) and `Webserver.ForwardedForHeader` (default `X-Forwarded-For`). When the connecting peer is a trusted proxy, the client IP recorded in request history, logs, QoS `ClientIp` rules, and source-IP session affinity is taken from the forwarded-for header. Default is empty, which keeps using the connecting peer address.
- Source-IP session affinity no longer trusts `X-Forwarded-For` from arbitrary clients; it now uses the resolved client IP, which only honors the header from trusted proxies.
- Added an unauthenticated health probe on every VMR base URL: `GET` or `HEAD` on `/v1.0/api/{vmr}/` returns `204` when the VMR has an active, healthy endpoint in the `Normal` service state and `503` otherwise. The probe skips authentication and QoS, uses no endpoint slot, and never reaches a model runner.
- Fixed QoS admission returning nothing but `429`s after a burst: the scheduler that releases queued requests is now supervised and restarts with backoff after any fault (previously a single unexpected exception stopped it for good), and every queued request is settled exactly once so a capacity permit can never be lost or granted twice.
- Requests now queue when every endpoint is at `MaxParallelRequests` instead of receiving an immediate `AllEndpointsAtCapacity` `429`, and an admitted request that finds its endpoint busy (for example, because another VMR shares it) waits for a free slot until the profile's `MaxQueueWaitMs` deadline instead of failing with `EndpointAtCapacity` straight away.
- QoS capacity now follows endpoint changes: it is re-read every 5 seconds and right after endpoint, endpoint group, VMR, or backup restore changes, without disturbing queued or in-flight requests. Editing a linked QoS profile moves waiting requests into the rebuilt runtime instead of dropping them, and a failed rebuild keeps the previous runtime serving.
- QoS rejections (`QosRejected`, `QosTimedOut`, `QosAborted`) and endpoint slot timeouts are now recorded in request history with their status code, denial reason, and a `QosAdmission` timeline stage; previously a QoS rejection left its history entry without a status.
- Added the `/v1.0/qosruntime` API (`GET /v1.0/qosruntime`, `GET /v1.0/qosruntime/{vmrId}`, `GET /v1.0/qosruntime/{vmrId}/history`) exposing each VMR's scheduler state, capacity in use, waiting requests, per-class admission counts and wait times, endpoint slot usage, and 24 hours of per-minute history.
- Added QoS runtime support to the C#, JavaScript, and Python SDKs (`ListQosRuntime`/`GetQosRuntime`/`GetQosRuntimeHistory` and their language equivalents), three read-only MCP tools (`conductor_list_qos_runtime`, `conductor_get_qos_runtime`, `conductor_get_qos_runtime_history`, which the MCP host enables through `ConductorMcpServer.ConfigureQosRuntime`), and a **QoS Runtime** folder in the Postman collection.
- Updated `QoSKit` from 0.2.0 to 0.2.1, which fixes queued work in a rate-limited low-latency priority class stalling until the next request arrived, plus several waiter and chain-pump race conditions.
- Added a **QoS Monitor** page to the dashboard showing live queueing and admission per VMR and per traffic class, with admissions and queue-wait charts and per-class and endpoint-slot tables.
- The Request History page's time range selector now sits above the summary and applies to the summary counts, the chart, the table, and bulk delete. The table now defaults to the last day.
- The dashboard now remembers the selected time range (Request History, Dashboard request chart, Request Analytics) and the rows-per-page setting for each table across visits and reloads, per browser.

## v0.5.0

- Set .NET project versions to `0.5.0` and bumped the Docker Compose image tags to `v0.5.0`.
- Added per-virtual-model-runner **QoS queueing**: a VMR can be linked to a reusable, tenant-scoped **QoS profile** that classifies incoming traffic and queues it (FIFO, priority, weighted-fair, class-based weighted-fair, low-latency, or weighted round robin, chainable into a hierarchy), releasing requests in scheduled order as endpoint capacity frees instead of rejecting immediately. Built on the [QoSKit](https://github.com/jchristn/qoskit) library.
- Classification is operator-defined: a request maps to a traffic class by a custom header, a specific credential, the requested model, a request-body attribute, the tenant, the user, the client IP, the API family, or the request type.
- Admission gates against the runner's existing endpoint capacity (the sum of endpoint `MaxParallelRequests`); a full queue or an expired wait deadline returns `429` with a `Retry-After` header. Queues are in-memory; only profile configuration is persisted.
- Seeded per tenant on startup and on tenant creation: a non-deletable **Default (FIFO)** profile that every VMR uses unless otherwise specified, a catalog of standard traffic classes (`realtime`, `human-interactive`, `agent-interactive`, `batch-time-bound`, `batch-background`, `default`), and a ready-to-use **Standard Workloads** low-latency profile. Existing VMRs are backfilled to the default; seeding does not resurrect deletions.
- Linking a QoS profile is required on VMR create/update (an unset profile is auto-assigned the tenant default; an unknown id is rejected).
- Added REST endpoints `/v1.0/qosprofiles` (CRUD, `validate`, `classifier-catalog`) and `/v1.0/qostrafficclasses` (CRUD), and a system-admin-only tenant purge (nuke) endpoint `POST /v1.0/tenants/{id}/purge` that requires the caller to echo the tenant id, refuses the reserved `default` tenant, and returns an itemized deletion report. Deleting a tenant now also removes its QoS configuration.
- All QoS configuration lives in the database across normalized tables (`qosprofiles` and its child tables plus `qostrafficclasses`), created by on-startup migrations across SQLite, PostgreSQL, SQL Server, and MySQL; nothing QoS-related is stored in `conductor.json`.
- QoS telemetry flows through the existing OpenTelemetry pipeline and is Prometheus-scrapable: QoSKit's per-class metrics and hop-by-hop traces are subscribed alongside new `conductor.qos.*` instruments (admissions, rejections, per-class wait duration, queue depth), and a proxied request gains an `inference.qos.admit` trace span.
- Added dashboard management for QoS: a **QoS Profiles** view (create/edit/duplicate/delete profiles with FIFO / Standard Workloads / two-tier-priority starter templates, a form-based classifier-rule editor, a live queue-topology diagram, and draft validation) and a **QoS Traffic Classes** view; the virtual model runner form gained a QoS profile selector.
- Added QoS tools to the MCP server (list/get/create/update/delete/validate QoS profiles and list/get/create/update/delete traffic classes) and QoS methods to the C#, JavaScript, and Python SDKs.
- Reorganized the provisioned Grafana dashboards into a single top-level **Conductor** folder (Database, HTTP & API, Inference & Proxy, QoS & Queueing, Routing & Load Balancing, Runtime & Process, Health & Endpoints all live directly inside it), and added the **QoS & Queueing** dashboard.
- Added `QOS_OVERVIEW.md` documenting what QoS does, how to configure it, and how to monitor it.
